# Skills Generation Specification

## Overview

This specification defines the agent skills generation system for the Human Evaluation Workshop. The system synthesizes modular skill files that workshop participants can integrate into their agents. Skills are generated by analyzing three evidence sources: the agent system prompt, aligned judge memory (MemAlign), and evaluated traces with human feedback.

Skills are **actionable playbooks** the agent executes at runtime for specific query types. They are not descriptions of what the agent does. Each skill encodes domain knowledge, quality standards, and lessons learned from human evaluation to make the agent better at handling a particular class of user requests.

## Core Concepts

### What is a Skill

A skill is a self-contained Markdown file with YAML frontmatter that provides runtime instructions for an AI agent. When the agent encounters a specific type of user query, it loads the relevant skill to guide its response. Skills are domain-agnostic: the generation system derives skill names, content, and scope entirely from the traces and judge feedback observed during the workshop.

### Skill Identification

Skills are identified by clustering real user queries from evaluated traces (Source 3) into distinct request patterns. Each pattern that requires a different reasoning approach becomes a candidate skill. The system then enriches each skill with quality criteria from the aligned judge (Source 2) and domain-specific instructions from the system prompt (Source 1) if the system prompt is available. The optimized system prompt is used if prompt optimization has already executed.

### Anti-patterns

The following types of skills should NOT be generated:
- **Meta-skills** about the agent's own quality or self-assessment (e.g., "evaluating-response-quality")
- **Vague capability descriptions** that restate the system prompt (e.g., "providing-strategic-recommendations")
- **Generic skills** not grounded in actual query patterns from the traces (e.g., "ensuring-high-quality-output")
- **Skills for unobserved query types** that do not appear in the trace data

## Data Model

### Database Schema

Table: `generated_skills`

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | String | PRIMARY KEY | UUID |
| `workshop_id` | String | FOREIGN KEY (workshops.id, CASCADE), NOT NULL | Workshop this skill belongs to |
| `name` | String | NOT NULL | Skill identifier (lowercase-with-hyphens) |
| `description` | Text | NOT NULL | Description with trigger conditions and benefit (max 1024 chars) |
| `filename` | String | NOT NULL | Skill filename (ends with .md) |
| `content` | Text | NOT NULL | Full skill markdown including YAML frontmatter |
| `generation_model` | String | NULLABLE | Model used to generate skill |
| `created_at` | DateTime | DEFAULT NOW() | Timestamp of creation |
| `updated_at` | DateTime | DEFAULT NOW(), ON UPDATE NOW() | Timestamp of last update |

Workshop column: `skills_generation_job_id` (String, NULLABLE) on `workshops` table stores the latest skills generation job ID for session persistence across tab switches and page reloads.

**Relationships:**
- `workshop_id` -> `workshops.id` with CASCADE DELETE (skills are deleted when workshop is deleted)

### Skill File Format

Each skill is stored as a Markdown file with YAML frontmatter:

```markdown
---
name: lowercase-with-hyphens
description: >
  When to load this skill: [specific trigger conditions from real queries].
  What it helps with: [concrete improvement this skill provides].
---

# [Skill Title]

## When to use
[Specific query patterns, keywords, or user intents that trigger this skill.]
[Drawn directly from the real queries in Source 3.]

## Instructions
[Step-by-step instructions the agent follows for this query type.]
[Be concrete: "Look up X, then compare Y, then format as Z".]
[Include conditional logic: "If the user asks for A, do B. If they ask for C, do D."]

## Quality bar
[What human experts rated highly for this type of query (from Source 2).]
[What they penalized. Be specific.]

## Common mistakes
[Failure patterns observed in low-scoring traces.]
[Each mistake should be a concrete "Do not..." statement.]
```

## Behavior

### Prompt Selection Priority

When `prompt_text` is not provided in the request, the system automatically selects a prompt in this order:

1. **Optimized prompt from GEPA** -- queries the most recent completed `PromptOptimizationRunDB` for this workshop
2. **Workshop judge prompt** -- falls back to the latest judge prompt from the tuning phase
3. **Empty string** -- generates skills without prompt context (last resort)

The selected source is logged as `Prompt source: optimized (from GEPA)`, `Prompt source: workshop judge prompt (no optimization run found)`, or `Prompt source: user-provided`.

### Authentication

The service uses the **stored user token** (from workshop intake) for all MLflow and UC operations, not the app's service principal. This is necessary because:
- The app's service principal typically lacks grants on facilitator-owned UC schemas
- Prompt registry operations, experiment access, and `get_scorer()` require the facilitator's permissions
- Each workshop stores its own token, so multi-tenant operation works without per-customer SP grants
- This avoid auth issues around the prompt registry observed during testing

The auth setup explicitly clears OAuth credentials (`DATABRICKS_CLIENT_ID`, `DATABRICKS_CLIENT_SECRET`) and sets `DATABRICKS_TOKEN` from the stored intake token.

### FMAPI Response Handling

Some models (e.g., Gemini) return `message.content` as a list of content blocks rather than a plain string:
```json
{"content": [{"type": "text", "text": "..."}]}
```

The service handles both formats, extracting the `text` field from each block and joining them.

### Job Persistence

The skills generation `job_id` is persisted on the `workshops.skills_generation_job_id` column when a job starts. The frontend calls `GET /{workshop_id}/latest-skills-generation-job` on page mount to recover the job state (ID, status, logs) after tab switches or page reloads. The polling effect then resumes if the job is still running.

## Skills Generation Service

### Location
`server/services/skills_generation_service.py`

### Class: `SkillsGenerationService`

#### Method: `generate_skills()`

**Signature:**
```python
def generate_skills(
    self,
    workshop_id: str,
    optimized_prompt: str,
    model_name: str,
    mlflow_config: Any,
    judge_names: Optional[List[str]] = None,
    judge_name: Optional[str] = None,
) -> Generator[Any, None, None]
```

**Parameters:**
- `workshop_id`: Workshop UUID
- `optimized_prompt`: System prompt text (optimized or fallback)
- `model_name`: Databricks FMAPI model name for skill generation
- `mlflow_config`: MLflow configuration (experiment_id, databricks_host, token)
- `judge_names`: List of aligned judge names (one per rubric question)
- `judge_name`: Fallback single judge name if judge_names not provided

**Returns:**
Generator that yields:
- `str` -- Log messages during execution
- `dict` -- Final result with structure:
  ```python
  {
      "success": bool,
      "phase": "skills",
      "skills_count": int,
      "skills": [
          {"name": str, "description": str, "filename": str},
          ...
      ],
      "error": str  # Only present if success=False
  }
  ```

**Process:**

1. **Configure MLflow** -- Set tracking URI, experiment, and auth (prefer stored user token)
2. **Source 1: System Prompt** -- Already provided as argument
3. **Source 2: Aligned Judge Memory**
   - Load judges using `mlflow.genai.scorers.get_scorer(name=..., experiment_id=...)`
   - Extract semantic memory (distilled guidelines)
   - If semantic memory not loaded, trigger lazy load with a dummy scorer call
   - Extract episodic memory (representative examples, limit 8)
   - Extract aligned instructions
4. **Source 3: Evaluated Traces** -- Built via `_build_traces_analysis()`
   - Query MLflow traces with `label='align'` first, fall back to `label='eval'`
   - Extract user queries, responses, tool calls, and assessment scores
   - Compute tool usage frequency and co-occurrence patterns
   - Identify high-scoring and low-scoring examples with rationales
5. **Generate Skills via FMAPI**
   - Call Databricks FMAPI endpoint with generation prompt
   - Handle list-of-blocks response format (Gemini compatibility)
   - Parse JSON array of skills from response
   - Validate each skill (filename, content, frontmatter)
6. **Write to Database** -- Via `_write_skills_to_db()`
   - Clear existing skills for workshop (atomic replace)
   - Insert new skills with SQLAlchemy ORM
   - Commit transaction

### Helper Methods

#### `_build_traces_analysis(workshop_id: str, mlflow_config: Any) -> str`

Extracts trace analysis from workshop data:
- Tool usage frequency
- Common tool co-occurrence patterns
- Representative user queries (first 10)
- Assessment score distribution
- High-scoring and low-scoring example rationales

#### `_extract_frontmatter(content: str) -> Tuple[str, str]`

Parses YAML frontmatter from skill content to extract `name` and `description`.

#### `_write_skills_to_db(workshop_id: str, skills: List[Dict], model_name: str) -> int`

Writes generated skills to database:
- Deletes existing skills for workshop
- Inserts new skills
- Returns count of skills written

## API Endpoints

### POST `/{workshop_id}/start-skills-generation`

**Description:** Start a skills generation job in the background

**Request Body:** `SkillsGenerationRequest`
```json
{
  "prompt_text": "optional explicit prompt text",
  "generation_model_name": "databricks-claude-sonnet-4-5",
  "judge_name": "workshop_judge"
}
```

**Parameters:**
- `prompt_text` (optional): Explicit prompt to use. If not provided, uses the prompt selection priority chain described above.
- `generation_model_name`: FMAPI model name for skills generation
- `judge_name`: Aligned judge name (defaults to workshop judge)

**Side effects:**
- Persists `skills_generation_job_id` on the workshop record for session recovery

**Response:**
```json
{
  "job_id": "uuid",
  "status": "running",
  "message": "Skills generation started. Poll GET /skills-generation-job/{job_id} for status."
}
```

**Error Responses:**
- `404 Not Found` -- Workshop not found
- `400 Bad Request` -- MLflow configuration or Databricks token not found

### GET `/{workshop_id}/skills-generation-job/{job_id}`

**Description:** Poll status and logs of a running skills generation job

**Parameters:**
- `workshop_id` (path): Workshop UUID
- `job_id` (path): Job UUID from start response
- `since_log_index` (query): Log index to fetch new logs from (for incremental polling)

**Response:**
```json
{
  "job_id": "uuid",
  "status": "running",
  "logs": ["log line 1", "log line 2"],
  "log_count": 42,
  "updated_at": 1234567890.123,
  "result": null,
  "error": null
}
```

**Status Values:**
- `running` -- Job in progress
- `completed` -- Job finished successfully
- `failed` -- Job encountered an error

### GET `/{workshop_id}/latest-skills-generation-job`

**Description:** Get the latest skills generation job for a workshop. Used by the frontend to recover job state after tab switches or page reloads.

**Response:**
```json
{
  "job_id": "uuid-or-null",
  "status": "running",
  "logs": ["all", "log", "lines"],
  "log_count": 42,
  "updated_at": 1234567890.123,
  "result": null,
  "error": null
}
```

Returns `{"job_id": null, "status": "none"}` if no skills generation job has been started for this workshop.

### GET `/{workshop_id}/generated-skills`

**Description:** Get all generated agent skills for a workshop

**Response:** `List[Dict[str, Any]]`
```json
[
  {
    "id": "uuid",
    "name": "skill-name",
    "description": "When to load: ... What it helps with: ...",
    "filename": "skill-name.md",
    "content": "---\nname: skill-name\n...",
    "generation_model": "databricks-claude-sonnet-4-5",
    "created_at": "2026-02-17T10:30:00Z"
  }
]
```

**Ordering:** Skills are ordered by `name` (alphabetical)

### GET `/{workshop_id}/generated-skills/{skill_name}`

**Description:** Get a single generated skill by name

**Error Responses:**
- `404 Not Found` -- Workshop or skill does not exist

## Skill Generation Prompt

### Philosophy

The prompt instructs the LLM to generate **actionable playbooks**, not capability descriptions. The identification process starts from real traces (Source 3) and clusters actual user queries into distinct patterns, then enriches each with judge quality criteria and system prompt instructions.

### Prompt Structure

```
You are generating runtime skill files that an AI agent loads on-demand...

PURPOSE: Each skill is a concrete instruction set the agent follows...

IMPORTANT DISTINCTION:
- BAD skill: "evaluating-response-quality" (judge concern, not agent task)
- BAD skill: "providing-strategic-recommendations" (too vague)
- GOOD skill: named after specific query patterns from traces
- GOOD skill: addresses recurring failure modes from low-scoring traces

=== SOURCE 1: AGENT SYSTEM PROMPT ===
{optimized_prompt}

=== SOURCE 2: QUALITY STANDARDS ===
{judge_guidelines}
{episodic_examples}

=== SOURCE 3: REAL USER INTERACTIONS ===
{traces_analysis}

SKILL IDENTIFICATION PROCESS:
1. Cluster real queries from Source 3 into distinct patterns
2. Check Source 2 for quality criteria per pattern
3. Check Source 1 for domain instructions per pattern
4. Write skill as instructions that produce high-scoring responses

RULES:
1. Ground every skill in actual query patterns from traces
2. No meta-skills about quality or self-assessment
3. No restating the system prompt
4. Target 4-7 skills
5. Self-contained skills
6. Name after user's task, not agent's capability

RETURN FORMAT: JSON array of {filename, content}
```

### Domain Agnosticism

The prompt contains no domain-specific examples. All skill names, content, and scope are derived from the traces and judge feedback provided at runtime. This ensures the system works for any agent domain (sports, finance, customer support, etc.).

## Validation Rules

### Skill Name Validation

- **Format:** Lowercase letters, numbers, and hyphens only
- **Max length:** 64 characters
- **Naming convention:** Named after the user's task, not the agent's capability
- **Normalization:** Spaces replaced with hyphens, converted to lowercase

### Skill Description Validation

- **Required:** Must not be empty
- **Max length:** 1024 characters
- **Content:** Must include trigger conditions (when to load) and concrete benefit
- **Fallback:** If missing, defaults to `"Skill: {name}"`

### Skill Content Validation

- **Required:** Must not be empty
- **Format:** Must include YAML frontmatter with `---` delimiters
- **Frontmatter:** Must contain `name` and `description` fields
- **Sections:** Should include When to use, Instructions, Quality bar, Common mistakes

### Filename Validation

- **Format:** Must end with `.md`
- **Normalization:** Spaces replaced with hyphens, converted to lowercase
- **Fallback:** If missing `.md` extension, it is appended

## Skill Count Guidelines

**Target:** 4-7 skills per workshop

**Rationale:**
- **Too few (< 4):** Skills are too broad to be useful for routing
- **Too many (> 10):** Skills overlap and discovery becomes noisy
- **Sweet spot (4-7):** Balanced granularity with preference for fewer, more specific skills

## Database Operations

### Atomic Replacement

When writing skills to the database:

```python
# Clear existing skills for workshop
db.query(GeneratedSkillDB).filter(
    GeneratedSkillDB.workshop_id == workshop_id
).delete()

# Insert new skills
for skill in skills:
    record = GeneratedSkillDB(
        id=str(uuid.uuid4()),
        workshop_id=workshop_id,
        name=skill["name"],
        description=skill["description"],
        filename=skill["filename"],
        content=skill["content"],
        generation_model=model_name,
    )
    db.add(record)

db.commit()
```

**Transaction behavior:**
- All deletes and inserts happen in a single transaction
- Rollback on any error
- No partial writes

### PostgreSQL DDL

The `generated_skills` table DDL is defined in `server/postgres_manager.py` and created during app startup. The `skills_generation_job_id` column on `workshops` is added via the `_COLUMN_MIGRATIONS` list.

## Success Criteria

### Functional Requirements

1. **Skills are generated** when manually triggered by the facilitator via the UI button
2. **All three sources are used** to ground skills in evidence
3. **Skills are validated** against format and content rules
4. **Skills are persisted** to database with atomic replacement
5. **Skills are retrievable** via API endpoints
6. **Job state persists** across tab switches and page reloads

### Quality Requirements

1. **Skills are actionable** -- Each is a playbook the agent executes, not a description
2. **Skills are domain-specific** -- Named after real query patterns, not generic capabilities
3. **Skills are grounded** -- Every skill traces back to observed user interactions
4. **Skills reflect quality standards** -- Judge feedback is encoded as quality bar and common mistakes
5. **No meta-skills** -- Skills about self-evaluation or quality assessment are excluded

### Non-Functional Requirements

1. **Non-fatal failures** -- Skills generation is an independent operation
2. **Streaming logs** -- Progress is visible during generation
3. **Transaction safety** -- Database writes are atomic
4. **Auth compatibility** -- Uses stored user token for multi-tenant UC access

## Error Scenarios

| Scenario | Behavior |
|----------|----------|
| MLflow not available | Return error, log warning |
| FMAPI call fails | Return error, log warning |
| FMAPI returns list content blocks | Extract text from blocks, continue |
| JSON parse error | Return error, log raw output preview |
| No skills generated | Return error |
| No valid skills after validation | Return error |
| Database write fails | Return error, rollback transaction |
| Judge memory unavailable | Log warning, generate skills without judge guidelines |
| No traces found | Log warning, generate with "No traces" analysis |
| Dual auth conflict (OAuth + PAT) | Clear OAuth, use stored PAT |
| Experiment not found | Fail gracefully if tracking URI not configured first |
